# EggMint – pixel-art Eierbär boot splash + login screen for Linux Mint 21.3

**Project page: <https://github.com/alexredl/Eggmint>**

<p align="center">
  <img src="screenshots/eierbaer.png" alt="The pixel-art Eierbär" width="336">

A hand-made pixel-art **Eierbär** replaces the Mint look. It has curly hair, bear ears, your
smile and mustache, a beaver nose, buck teeth, an egg in its paws and a beaver tail, and it sits
in a stick nest.

| Screen | What you get |
|---|---|
| **Boot** (instead of the Mint logo) | The Eierbär bobbing gently; a big **mustache loading bar** fills with brown as the system boots, and both mustaches twitch |
| **Shutdown / reboot** | "BYE BYE!" / "SEE YOU IN A SEC!" with a looping mustache |
| **Disk password** (only if your disk is encrypted) | Brown pixel input box, typed characters shown as little **eggs** |
| **Login screen** | Pixel landscape (mountains, pines, lake) with the Eierbär, brown pixel password field, EGGMINT logo |

See `screenshots/`. The sprite is drawn by `tools/sprite.py`; every image is generated by
`tools/gen_assets.py`.

**Tested in the VirtualBox VM "EggMint"** (Linux Mint 21.3 Cinnamon, the same release as your PC):
- installed from the running system, rebooted, logged in
- uninstalled and reinstalled
- **installed from a live session (Mint ISO as a "USB stick")**, then booted the system and logged in
- **install + uninstall roundtrips from the live session: every file/folder/link of the system
  (585,000+) was identical before and after** (contents, sizes, permissions, owners, timestamps)
- uninstall from the live stick of an install made on the running PC (and vice versa)

No compiling. No Mint file is overwritten.

## Four scripts, two matching pairs

|  | on the running PC (logged in) | from a live USB stick (PC's own system not started) |
|---|---|---|
| **install** | `sudo ./install.sh [--avatar USER]` | `sudo ./install-from-live.sh /dev/XXX [--avatar USER]` |
| **uninstall** | `sudo /var/eggmint/uninstall.sh` (or `sudo ./uninstall.sh` in the project folder) | `sudo ./uninstall-from-live.sh /dev/XXX` |

**You don't need to keep the project folder or USB stick for uninstalling.** Installing leaves
a complete copy of this project in **`/var/eggmint/`** on your system, with the backup in
**`/var/eggmint/backup/`**. Uninstalling removes `/var/eggmint/` completely.

Each pair does **exactly the same thing to your system**: the live versions run the very same
`install.sh` / `uninstall.sh` inside your system. You can mix them freely: install on the PC and
uninstall from the stick, or the other way round. All four combinations were tested in the VM.

### A) On the running PC

1. Copy the `eggmint-theme` folder to your PC (anywhere in your home folder).
2. Right-click inside the folder → *Open in Terminal*, then:
   ```bash
   chmod +x *.sh
   sudo ./install.sh
   ```
   Optional: `sudo ./install.sh --avatar YOUR_USERNAME` also makes the Eierbär your user picture
   (Cinnamon menu / user settings; Mint's login screen doesn't show user pictures).
3. Reboot.

Undo (any time later, no USB stick needed): `sudo /var/eggmint/uninstall.sh`, then reboot.

### B) From a live USB stick

1. Boot the PC from a Linux Mint USB stick ("Start Linux Mint"; on most PCs F12/F11/F8/Esc
   at power-on opens the boot menu where you pick the stick).
2. Copy the `eggmint-theme` folder into the live session's home folder, open a terminal there:
   ```bash
   chmod +x *.sh
   sudo ./install-from-live.sh
   ```
   **Without a partition argument both live scripts change nothing.** They only list your
   partitions and **find the installed Mint system**:
   ```
     -> /dev/nvme0n1p2   (Linux Mint 21.3)
          users:       alex (Alex Redl)
          boot splash: mint-logo.plymouth
          EggMint:     not installed
   ```
3. Install into that partition:
   ```bash
   sudo ./install-from-live.sh /dev/nvme0n1p2
   sudo ./install-from-live.sh /dev/nvme0n1p2 --avatar alex     # optional: user picture too
   ```
4. Shut down, remove the stick, boot normally.

Undo from the stick: `sudo ./uninstall-from-live.sh /dev/nvme0n1p2`. It uses the `uninstall.sh`
stored in `/var/eggmint/` on your system, i.e. exactly the version that did the install.
Or boot normally and run `sudo /var/eggmint/uninstall.sh`.

### What exactly the live scripts do (and change)

On **your installed system** they change exactly what `install.sh` / `uninstall.sh` change,
nothing more (see "What install.sh does" below). In the **live session** (RAM only, gone at
shutdown) they temporarily:

1. mount your partition at `/mnt/eggmint-target`; mount a separate `/boot` partition too if
   your `fstab` has one; handle btrfs `@` subvolumes
2. bind the live session's `/dev`, `/proc`, `/sys`, `/run` into it, so programs inside work
3. copy the package to `/run/eggmint-pkg`. `/run` is RAM, so nothing temporary lands on your disk
4. `chroot` into your system and run `install.sh` (or `uninstall.sh`) there. That means your
   system's own `update-alternatives` and `update-initramfs` do the work, exactly as if it were
   running
5. delete the RAM copy and unmount everything again, even if something failed

Before mounting they refuse if the partition is already mounted (e.g. opened in the file manager)
or isn't a Linux Mint system. The shared code lives in `live-common.sh`.

**Encrypted disk (LUKS)?** The finder can't look inside it. Unlock it first, then use the unlocked
device:
```bash
sudo cryptsetup open /dev/nvme0n1p3 cryptroot      # asks for your disk password
sudo vgchange -ay                                  # only if it uses LVM ("vgubuntu"/"vgmint")
sudo ./install-from-live.sh                        # now lists /dev/mapper/... devices
```

### Which users exist? (from the live stick)

`sudo ./install-from-live.sh` or `sudo ./uninstall-from-live.sh` (no arguments) prints them, as
shown above. By hand:
```bash
sudo mount -o ro /dev/nvme0n1p2 /mnt
awk -F: '$3 >= 1000 && $3 < 60000 {print $1, "-", $5}' /mnt/etc/passwd
sudo umount /mnt
```
Real (human) users have IDs from 1000 up. Everything below 1000 is a system account.

## What is Plymouth / a `.plymouth` file? What if it's not installed?

**Plymouth** is the program that draws the boot and shutdown screens: the Mint logo you see today
is Plymouth running the theme `mint-logo`. It starts very early, before your disk is even mounted,
from the **initramfs** (`/boot/initrd.img-*`), a small archive the kernel loads first. That's why
themes have to be copied *into* that archive with `update-initramfs`. Just dropping files on the
disk does nothing.

A **`.plymouth` file** is a theme's small description file (plain text, like an .ini). Ours,
`eggmint.plymouth`, says "this theme uses the *script* plugin, run `eggmint.script` with images
from this folder". `eggmint.script` is the animation written in Plymouth's little scripting
language: plain text, nothing compiled. Which theme is active is a symlink managed by
`update-alternatives` (`/etc/alternatives/default.plymouth`).

**If Plymouth isn't installed:** every Linux Mint install has it (the Mint logo at boot comes from
it). If yours somehow didn't, `install.sh` stops at its first check ("no default.plymouth
alternative found") **before changing anything**. The live-stick finder also tells you
("Plymouth not installed").

## What `install.sh` does, exactly

1. **Safety checks** (stops before touching anything if one fails): runs as root; it's Linux Mint;
   all package files present; Plymouth present; `/boot/initrd.img-*` present; not already installed.
2. **Records the current state** in `/var/eggmint/backup/` (readable by root only):
   - which boot theme is active, and whether it's set manually or automatically
   - a checksum of the package database
   - whether `/etc/lightdm/slick-greeter.conf` exists, plus a copy of it if so
   - a copy of every `/boot/initrd.img-*`
   - the modification times of every folder/link it will touch
   - a copy of `/var/log/alternatives.log`
   - with `--avatar`: copies of that user's picture settings

   and copies **this whole project to `/var/eggmint/`** (scripts, README, images, tools;
   about 0.5 MB). The backup is mostly the boot archive copies: roughly 125 MB per installed
   kernel.
3. **Adds the boot theme**: new folder `/usr/share/plymouth/themes/eggmint/` (script + 90 images).
4. **Selects it**: `update-alternatives --install … eggmint.plymouth 100` and `--set …`
   (that's the official switch Mint/Ubuntu use for boot themes), then `update-initramfs -u -k all`
   to put it into the boot archives. This is the same thing Mint does after every kernel update.
5. **Adds the login screen look**:
   - new folder `/usr/share/eggmint/` (background, logo, user picture)
   - new GTK theme `/usr/share/themes/EggMint/`, plain CSS on top of Mint-Y-Aqua and only used
     by the login screen
   - sets these keys in `/etc/lightdm/slick-greeter.conf` (the file doesn't exist on a default
     install and is created): `background`, `background-color`, `draw-user-backgrounds=false`,
     `draw-grid=false`, `logo`, `theme-name=EggMint`, `font-name`
6. **Optional `--avatar USER`**: copies the picture to `/var/lib/AccountsService/icons/USER` and
   points `Icon=` in `/var/lib/AccountsService/users/USER` at it.

Your desktop, your home folder and your settings are not touched.

## Does `uninstall.sh` really revert everything?

Yes. It puts back:
- the login screen config (or deletes it if it didn't exist before)
- the user picture settings
- the boot theme, in its original auto/manual mode
- the **original boot archives, byte-for-byte**
- the alternatives log
- the timestamps of every touched folder and link

Then it deletes all EggMint files **and `/var/eggmint/` itself** (project copy + backup). When
started as `/var/eggmint/uninstall.sh` it first moves itself to RAM (`/run`), so deleting its
own folder is safe.

Proven in the VM:
- **Live stick** (install-from-live → uninstall-from-live): a fingerprint of the whole system was
  **identical** before and after. That's every file, folder and link (585,221 entries): size,
  permissions, owner and modification time, plus a content checksum for `/etc`, `/boot`,
  `/var/lib`, `/var/backups` and `/usr/share/plymouth|themes`.
- **Running PC** (`install.sh` → `/var/eggmint/uninstall.sh`): the same fingerprint of
  everything EggMint can touch (497,706 entries) was **identical** before and after.

What can remain, honestly:
- **Done from the running system:** your use of `sudo` is logged by the system itself
  (`/var/log/auth.log`, systemd journal), as it is for every sudo command. Done **from the live
  stick**, nothing is logged on your disk.
- If you **install system updates between install and uninstall**, uninstall rebuilds the boot
  archives instead of restoring the old copies, because restoring them would undo the updates.
  They work the same; only the bytes differ, which updates change anyway.
- Low-level file-system metadata that no tool lets you set (inode change times, the ext4
  "last mounted" counter) changes. That happens on every boot anyway.

## If something goes wrong (very unlikely)

| Problem | What you'd see | Fix |
|---|---|---|
| Boot splash fails | System boots normally with a black/text screen instead | `sudo /var/eggmint/uninstall.sh` |
| Login screen looks wrong | Login still works, just looks odd | Log in, `sudo /var/eggmint/uninstall.sh` |
| Login screen doesn't appear | Black screen after boot | **Ctrl+Alt+F2**, log in, `sudo /var/eggmint/uninstall.sh && sudo reboot`, or use the live stick: `sudo ./uninstall-from-live.sh /dev/XXX` |
| Want to skip the splash for one boot | — | In the GRUB menu (hold **Shift**/**Esc** while booting) press **e**, delete `splash`, press **F10** |
